# Cost Optimization Runbook

## Monthly Cost Review Process

Run this process on the first Monday of each month.

### Step 1 — Review Budget Status

```bash
# List all budgets and current consumption
az consumption budget list --query \
  "[].{Name:name, Amount:amount, CurrentSpend:currentSpend.amount, Limit:amount}" \
  --output table
```

### Step 2 — Identify Top Cost Drivers

```bash
# Top 20 resources by cost (last 30 days)
az consumption usage list \
  --start-date $(date -d '-30 days' +%Y-%m-%d) \
  --end-date $(date +%Y-%m-%d) \
  --top 20 \
  --query "sort_by(@, &pretaxCost)[-20:].{Service:product, Resource:instanceName, Cost:pretaxCost, Currency:currency}" \
  --output table
```

### Step 3 — Review Azure Advisor Recommendations

```bash
# List cost recommendations
az advisor recommendation list \
  --category Cost \
  --query "[].{Impact:impact, Description:shortDescription.problem, Savings:extendedProperties.savingsAmount}" \
  --output table
```

### Step 4 — Identify Idle/Orphaned Resources

```powershell
# Run the cleanup identification runbook
pwsh automation/runbooks/Cleanup-StaleResources.ps1 -DryRun $true -DaysOld 90
```

### Step 5 — Review Reserved Instance Coverage

Check Reserved Instance coverage in Cost Management:
- Navigate to: Cost Management → Reservations → Utilization
- Target: >85% utilization on all active reservations
- Action: Purchase additional RIs for underserved workloads

### Step 6 — Tag Compliance Report

```bash
# Resources missing required tags
az policy state list \
  --filter "policyDefinitionName eq 'require-tags-on-resources' and complianceState eq 'NonCompliant'" \
  --query "[].{Resource:resourceId, NonCompliant:complianceState}" \
  --output table
```

## Cost Optimization Strategies by Service

### Virtual Machines
| Optimization | Action | Savings Potential |
|-------------|--------|------------------|
| Right-size oversized VMs | Use Advisor recommendations | 20–40% |
| Shut down idle VMs | Tag `AutoShutdown: true`, auto-shutdown policy | 60–80% (nights/weekends) |
| Use Spot Instances | For batch/non-critical workloads | 60–90% |
| Reserved Instances | 1-year for stable workloads | 30–40% |
| Azure Hybrid Benefit | Apply existing Windows Server / SQL licenses | 40–55% |

### Storage
| Optimization | Action | Savings Potential |
|-------------|--------|------------------|
| Lifecycle policies | Move blobs to Cool/Archive tiers automatically | 50–80% |
| Delete orphaned disks | Identify unattached managed disks | Full cost elimination |
| Storage tiering | Review hot vs. cool vs. archive usage | 30–60% |
| Compression | Enable compression for applicable data | Variable |

### Networking
| Optimization | Action | Savings Potential |
|-------------|--------|------------------|
| VNet peering vs VPN | Use VNet peering (cheaper) when possible | 40–60% |
| Egress optimization | Minimize cross-region egress | Variable |
| ExpressRoute sizing | Right-size circuit bandwidth | Variable |
| Remove unused Public IPs | Delete unassociated PIPs | $3–5/month each |

### PaaS Services
| Optimization | Action | Savings Potential |
|-------------|--------|------------------|
| Azure SQL DTU → vCore | Enables Azure Hybrid Benefit | 20–40% |
| Azure Kubernetes Service | Use Spot node pools for non-critical pods | 60–90% |
| App Service Plan | Consolidate apps onto shared plans | 50–70% |
| Azure Functions | Use Consumption plan for sporadic workloads | Pay-per-execution |

## Tagging for Cost Allocation

All resources must have these tags for accurate cost attribution:

```
Environment:       prod | staging | dev | sandbox
CostCenter:        CC-XXXXX (Finance-assigned code)
Owner:             team@contoso.com
Application:       application-name
ManagedBy:         platform-team | workload-team
```

Cost reports are generated by filtering Cost Management by tag values.

## Budget Alert Response

| Alert Threshold | Action |
|----------------|--------|
| 50% | Review — is spend on track? |
| 75% | Identify top 5 cost drivers, assess if expected |
| 90% | Freeze non-essential new resource creation, escalate to FinOps lead |
| 100% (forecast) | Emergency review — stop all non-production workloads if needed |
